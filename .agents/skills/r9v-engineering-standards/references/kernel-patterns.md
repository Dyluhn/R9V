# Kernel patterns

The shapes every T1 kernel and every T2 emitter uses. They exist so that determinism and the numerics contract are structural, not something each kernel re-derives. Names below are the leaf-wrapper names from `r9v-kgen/src/leaf/`; T1 uses the portable equivalents in `kernels/reference/common.hip`.

## Reductions

**Within a wave, fixed order.** A butterfly with a fixed offset sequence yields the same bits on every lane and every run. Never `__shfl_xor` with a data-dependent mask; never let the compiler pick.

```cpp
// Reduce `v` across the wave into lane 0, in a fixed offset order.
template <typename T> __device__ inline T wave_reduce_sum(T v) {
    #pragma unroll
    for (int off = WAVE_SIZE / 2; off > 0; off >>= 1)   // WAVE_SIZE from the descriptor
        v += wave_shfl_down(v, off);                     // leaf wrapper; deterministic
    return v;                                            // valid on lane 0
}
```

**Across waves, through LDS, in ascending wave order.**

```cpp
__shared__ float partial[WAVES_PER_WG];
if (lane == 0) partial[wave] = v;
__syncthreads();
if (wave == 0 && lane == 0) {
    float s = 0.f;
    #pragma unroll
    for (int w = 0; w < WAVES_PER_WG; ++w) s += partial[w];   // ascending, always
    out[row] = s;
}
```

**Across work-groups, never atomics.** Write fixed-shape partials to the workspace at `[split_idx][row]`; a separate reduce kernel sums `split_idx` ascending.

```cpp
// split-K partial writer
partials[k_split * N + row] = acc;                 // one writer per slot, no atomics
// reduce kernel (generated from the same TileConfig)
float s = 0.f;
for (int k = 0; k < K_SPLITS; ++k) s += partials[k * N + row];   // ascending
```

## Online softmax (attention)

```cpp
float m = -INFINITY, l = 0.f;
float acc[DV_PER_LANE] = {0};
for (int blk = blk_begin; blk < blk_end; ++blk) {            // ascending block order, always
    float s = qk_logit(q, k_frag(blk), k_scale[blk]);        // f32; per-token K scale applied here
    if (SOFTCAP) s = SOFTCAP * tanhf(s / SOFTCAP);           // before the max, per spec 1 §6.3
    s = masked(s, blk, /*tree or causal*/) ? -INFINITY : s;
    float m_new = fmaxf(m, s);
    float corr  = __expf(m - m_new);                         // opted-in fast exp; contract allows
    float p     = __expf(s - m_new);
    l = l * corr + p;
    pv_accumulate(acc, corr, p * v_scale[blk], v_frag(blk)); // V scale applied to P's column
    m = m_new;
}
// epilogue: acc / l  (f32), then cast once
```

Split-KV merges partials `(m_i, l_i, acc_i)` in ascending partition order:

```cpp
float m = m_0, l = l_0; acc = acc_0;
for (int i = 1; i < P; ++i) {
    float m_new = fmaxf(m, m_i);
    float a = __expf(m - m_new), b = __expf(m_i - m_new);
    l = l * a + l_i * b;  acc = acc * a + acc_i * b;  m = m_new;
}
```

## Fragment loads from `L1`

Spec 2 §2.2: lane `l` of a tile holds `W[n = l % 16, k = (l / 16) * 8 .. +8]`. That is exactly one contiguous load per lane.

```cpp
// int8: 8 K-consecutive weights of one row -> one 64-bit load, already in B-fragment order.
const uint2 wv = *reinterpret_cast<const uint2*>(tile_base + lane * 8);
// int4: 8 nibbles -> one 32-bit load; unpack only on the dot4 path, feed iu4 WMMA directly.
const uint32_t wn = *reinterpret_cast<const uint32_t*>(tile_base + lane * 4);
```

If the emitted code needs `__shfl`, LDS staging or a permute to assemble a B fragment from `L1`, the layout is being used wrong; stop and re-read spec 2 §2.2 and the A0.S1 spike result.

## GEMV inner loop (dot4)

```cpp
// per lane: 8 weights (uint2) and the matching 8 activation bytes broadcast from LDS
acc = dot4_i8(acc, wv.x, xv.x);        // leaf wrapper -> v_dot4_i32_i8
acc = dot4_i8(acc, wv.y, xv.y);
// PerToken: accumulate the whole K in i32, scale once in f32 at the end.
// PerBlock32: every 32 K-elements, acc_f32 += float(acc) * w_scale[blk] * x_scale[blk]; acc = 0;  (ascending blk)
```

`I4_K`: `acc_x = Σx` per 32-block computed once per token per block; `out = d*sc*(x·q) − dmin*mn*acc_x` in f32, blocks summed ascending.

## ABI usage

```cpp
struct matmul_7f3a9c_args {          // generated by kgen::abi; shapes are baked into the variant
    const uint8_t* __restrict__ w;   // L1 values, 256-byte aligned
    const uint8_t* __restrict__ w_scales;
    const int8_t*  __restrict__ x;   // PerToken i8
    const float*   __restrict__ x_scale;
    float*         __restrict__ y;
    float*         __restrict__ workspace;   // fixed-size, from the scheduler arena
};
extern "C" __global__ void matmul_7f3a9c(matmul_7f3a9c_args a) {
    const uint8_t* w = (const uint8_t*)__builtin_assume_aligned(a.w, 256);
    ...
}
```

No other parameters. No `extern __shared__` sized at launch beyond the variant's declared LDS. No allocation.

## Tree masks

`BatchMeta.tree` provides `parents[T]`; the scheduler also builds an ancestor bitmask per sequence. In-kernel: a query row `i` attends to context positions `< ctx_len` (causal) plus scratch positions `j` where `ancestor_mask[i] & (1u << j)` is set. Never derive tree structure from positions.

## Cache scales (fp8 K/V)

Per spec 1 §6.3: WMMA runs on raw e4m3 fragments. The per-(token, head) f16 scale for K multiplies the logit column after QKᵀ; the scale for V multiplies P's column before PV. Do not dequantize K or V to f16 in registers on the fast path; that is the parity path's job, not this one.

## Emitted-source hygiene

- `constexpr` block at the top: `WAVE_SIZE`, `LDS_BYTES`, `BM/BN/BK`, `K_SPLITS`, each with `// from <descriptor field | TileConfig field>`.
- One comment per phase: load, compute, reduce, epilogue.
- No macros beyond the leaf wrappers' includes.
- The reduce kernel for a split variant is emitted next to it and shares its constants.
