# Acceptance checklist

Walk every item. Each is a yes/no with a "how to verify" that does not rely on the PR body's claims. A card is accepted only when every applicable item is yes. Copy the relevant sections into the PR body; CI and the autonomous acceptance audit verify them from repository evidence. No human review or sign-off is required.

Items marked **[API]** apply only to API cards; **[GPU]** only to cards with `GPU: yes`; **[KERNEL]** only to cards that emit or write HIP.

## A. Scope and boundaries

| # | item | how to verify |
|---|---|---|
| A1 | The diff touches only the crates listed on the card, plus their tests and fixtures, plus files the card explicitly names (`SPEC-ISSUES.md`, workflow files, docs). | `git diff --name-only <base>` against the card's crate list. |
| A2 | Nothing under `specs/` changed (for A0.1 bootstrap only: pure addition of seeded specs is permitted when claimed in Deliverables). | `git diff --name-only <base> -- specs/` is empty (for A0.1: every change under `specs/` is status `A` and Deliverables claims `specs/` seeding). |
| A3 | No new op, dtype, scheme, layout id, state kind, `verify` method, config setting, metadata key, or proposer kind was introduced. | Grep the diff for additions to the enums and tables named in `spec-map.md` §Closed sets. |
| A4 | Every card in `deps` is merged to `main`. | Card ids in the breakdown vs merged PR titles. |
| A5 | No hand edits to `kernels/gen/`, `tune/`, `bench/baselines/`, `docs/config.md`, `SUPPORT.md`, `support/` unless the card owns that artifact, in which case it was regenerated by the named `xtask` command. | Diff paths; for owned artifacts, `cargo xtask gen` / `xtask docs` / `xtask support-matrix` reproduce the committed bytes. |
| A6 | `unsafe` appears only in `r9v-hip` and `r9v-t0` SIMD modules; inline asm only in `r9v-kgen/src/leaf/`. | `scripts/check_card.py`; `grep -rn "unsafe\|asm!" ` on the diff. |
| A7 | No new dependency without a justification line in the PR; `cargo deny check` passes (for A0.1 bootstrap only: `New dependencies: none` is permitted when `Cargo.lock` contains no registry/git source entries). | `git diff <base> -- Cargo.lock` and the PR body's dependency section (for A0.1: verify `Cargo.lock` contains no registry/git source entries). |
| A8 | No hardware constants outside `ArchDescriptor`/topology (wave size, LDS bytes, VGPR counts, bandwidth, instruction availability). | Grep the diff for `32`, `64`, `640`, `gfx1201` in kernel-adjacent code and check each is descriptor-driven. |
| A9 | The card's size class is plausible for the diff. | Line count vs the card's S/M/L; a large mismatch needs an explanation in the PR. |

## B. Tests

| # | item | how to verify |
|---|---|---|
| B1 | Every test named in the card's "done when" exists, with a descriptive name that maps to the card's wording. | Open the test files; match names to the card text. |
| B2 | Each test is in the correct tier: CPU-runnable tests under the workspace's normal `cargo test`; GPU tests under `tests/gpu/` and the `gpu/gfx1201` workflow. | File locations and workflow includes. |
| B3 | The tests fail without the change (they test the change, not the harness). | Revert the implementation locally or stub it; observe failures. |
| B4 | Op-level tests use the shared harness (card A1.10): golden vs T0, batch invariance, determinism, shape fuzz where applicable. No bespoke comparison loops. | Grep for the harness entry points in the test files. |
| B5 | Fixtures are seeded and deterministic; no test depends on wall-clock, environment, network, or files outside the fixture directories named in `CONVENTIONS.md`. | Read the fixture generation; run the tests twice. |
| B6 | No `#[ignore]` on a test the card names; no test skipped with a runtime condition other than "GPU absent" for GPU tests. | Grep for `#[ignore]`, `skip`, `return` guards. |
| B7 | Tolerances come from the spec 1 §6.1 table (as data), not literals in the test. | Grep for numeric tolerances in test code. |

## C. Determinism and numerics

| # | item | how to verify |
|---|---|---|
| C1 | No iteration over `HashMap`/`HashSet` (or any unordered container) affects output values or order. | Grep for `HashMap`, `HashSet`, `.iter()` on them in non-test code; check each use. |
| C2 | Reductions have a fixed order stated in code or doc comment; nothing sums in whatever order a parallel iterator yields. | Grep for `par_iter`, `rayon`, atomics; check reductions. |
| C3 | Accumulation dtypes and scale-application order match spec 1 §6 for the op(s) involved. | Read the arithmetic against the spec section. |
| C4 | RNG is seeded and counter-based where the spec requires (`Philox4x32` keyed by `(seq, step, draw)` for sampling). | Grep for `rand::thread_rng`, `random()`; none in non-test code. |
| C5 | Functions the spec calls pure (builder, partitioner, planner, cost model, repack rules) perform no I/O, logging, or clock reads. | Read imports and bodies of those modules. |
| C6 | Batch invariance holds for any op or executor change: the harness's alone/padded/embedded test is present and green. | Test exists and passes. |

## D. Code quality

| # | item | how to verify |
|---|---|---|
| D1 | `cargo fmt --check`, `cargo clippy -D warnings`, `cargo deny check` pass. | CI. |
| D2 | Errors use the `r9v-common` error type; no `unwrap()`/`expect()`/`panic!` on data that originates from a file, the network, a request, or a device. | Grep for `unwrap()`, `expect(`, `panic!` in non-test code and check each. |
| D3 | Refusals and validation errors report all failures with numbers (required, available, shortfall; every missing name), not the first one. | Read the error construction paths. |
| D4 | Public items have doc comments naming their spec section. | Grep `pub ` without a preceding `///`. |
| D5 | No `todo!()`, `unimplemented!()` or `TODO` without the later card id that explicitly owns the deferred behavior. | Grep. |
| D6 | Naming, module layout, logging fields and test layout follow `CONVENTIONS.md`. | Compare with the conventions file. |
| D7 | The implementation matches the spec-defined public surface; downstream work did not redesign it. | Compare public modules to the owning spec sections and API-shape tests. |
| D8 | No duplicated logic that already exists in `r9v-common` or the crate. | Skim for re-implemented helpers (hashing, byte parsing, ids). |

## E. Documentation and record

| # | item | how to verify |
|---|---|---|
| E1 | Every `DECISION(<card>)` comment in implementation source files in the diff is listed in the PR body under "Decisions" (documentation examples in Markdown/reference files are excluded). | `scripts/check_card.py`. |
| E2 | Each `DECISION` concerns something the spec leaves open, not something it states. | Read each against the cited spec section. |
| E3 | Every `SPEC-ISSUES.md` entry the card added follows the template and proposes a resolution. | Read the entries. |
| E4 | Commits are `<card id>: <summary>` with `Signed-off-by`. | `git log <base>..HEAD`. |
| E5 | The PR body follows `pr-template.md` and answers "which spec sections". | Read the PR. |
| E6 | No performance claim without a receipt path; observations are labelled as observations. | Read commit messages, comments, PR body. |

## F. GPU cards **[GPU]**

| # | item | how to verify |
|---|---|---|
| F1 | The PR body states which tests ran where (hosted, stub device, compile-only) and which are pending on the runner. | Read the PR. |
| F2 | The runner test exists under `tests/gpu/` or as a harness invocation the workflow picks up. | File exists; workflow includes it. |
| F3 | The card is labelled "ready for runner", not "done", until the runner is green. | PR label / status. |
| F4 | Any measured number in the PR names the machine fingerprint and the bench command that produced it. | Read the PR. |

## G. Kernel cards **[KERNEL]**

| # | item | how to verify |
|---|---|---|
| G1 | Emitted source under `kernels/gen/` was produced by `cargo xtask gen` and regenerates byte-identically in CI. | CI regenerate-and-diff. |
| G2 | Arch-specific instructions appear only through leaf wrappers; the emitter body is plain HIP C++. | Grep the emitted source for `__builtin_amdgcn_` and `asm` outside the leaf include. |
| G3 | Every tile config in the search space is deterministic (no atomics into output, split-K via fixed partials + tree reduce). | Read the emitter's reduction paths. |
| G4 | The variant passes golden, batch-invariance, determinism and shape gates on the runner before being marked validated. | Runner results. |
| G5 | Workspaces are fixed-size per bucket and come from the arena; the kernel allocates nothing. | Read the ABI struct and emitter. |
| G6 | Launch geometry is recorded in the tune entry and replays identically from the launch list. | Tune file diff; replay test. |

## H. API-bearing cards **[API]**

| # | item | how to verify |
|---|---|---|
| H1 | Every public type, trait and function the card's spec sections describe is present, with a doc comment naming the section. | Walk the spec sections against `pub` items. |
| H2 | Every behavior owned by the card is implemented; any deferred body names the later card that owns it. | Grep for stubs and map each allowed deferral to the breakdown. |
| H3 | Closed sets are enums; opaque handles are opaque; pure functions take and return values; immutables are not `&mut`. | Read the signatures. |
| H4 | `tests/api_shape.rs` exists and asserts the `Send`/`Sync` requirements the spec states. | File exists; test compiles. |
| H5 | The card's API-shape tests pass; cross-crate cohesion is assigned to A6.7a before freeze. | Test output and the A6.7a dependency. |

## I. Final

| # | item | how to verify |
|---|---|---|
| I1 | `scripts/check_card.py --card <id> --base main --pr-body <file>` passes on the final commit. | Run it. |
| I2 | The card's "done when" is satisfied word for word, not approximately. | Read the card; map each clause to an artifact. |
| I3 | Nothing in the change contradicts the specs. Any genuine contradiction is a `SPEC-ISSUES.md` entry and blocks only its affected dependency line. | Autonomous acceptance audit against the cited spec sections. |
